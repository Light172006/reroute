# Reroute Agent System: Build Plan and Specification Analysis

## 1. System Understanding (Executive Summary)

Reroute is an adaptive, agentic travel planning system designed for dynamic environments where real-world disruptions break static plans. The system operates in two core operational phases: generation and continuous adaptation. During initial generation, user preferences (destination, dates, budget, pace, vibe tags) are ingested, candidates are researched from a curated catalog or live tools, an initial day-by-day itinerary draft is generated by an LLM, and deterministic validation and budget rules verify feasibility within a bounded correction loop (up to 3 iterations).

During monitoring and adaptation, real-world signals (precipitation, snowfall, low visibility, road or pass closures, opening-hours updates, travel delays, and expense burn) are evaluated against active itinerary items. The impact analyzer deterministically identifies affected items. The replanner LLM modifies only affected, unlocked items while keeping unaffected items byte-identical. Changes are packaged into a structured proposal with before-and-after diffs, cost delta, and plain-language explanations. Crucially, no changes are applied autonomously: the replan graph pauses using LangGraph's interrupt() mechanism for human-in-the-loop approval, rejection, or alternative generation. A ReAct-based chat agent supports conversational queries and redirects manual modifications through the proposal flow. The design prioritizes determinism, safety, strict contracts, and graceful multi-tier LLM failover.

## 2. Module-by-Module Build Plan

1. **Scaffolding and Configuration (`agents/`)**:
   - `pyproject.toml`: Define pinned dependencies (langchain, langgraph, pydantic v2, httpx, tenacity, pytest, ruff, mypy, etc.).
   - `.env.example`: Template for environment variables and model fallback chains.
   - `reroute_agents/config.py`: Environment-driven settings with thresholds and mock flags.
   - `reroute_agents/state.py`: Shared Pydantic models (TripSpec, DraftItem, ItineraryDraft, Violation, DisruptionEvent, InjectedSignals, ReplanProposal, DiffItem) and LangGraph state TypedDicts (PlanState, ReplanState, ChatState).
   - `reroute_agents/events.py`: AgentEvent models, SSE formatting, and event emission helpers.
   - `reroute_agents/llm.py`: Tier-based LLM gateway (small, strong, local) with fallback chains, tenacity retry/backoff, token bucket limiter, structured output, and FakeLLM for tests.
   - `reroute_agents/repositories/`: Repository protocols (`interfaces.py`) and memory implementations (`in_memory.py`) for trips, versions, items, proposals, disruptions, catalog, expenses, cache, and run events.

2. **Deterministic Rules Engine (`reroute_agents/rules/`)**:
   - `validator_rules.py`: Overlap detection, opening hours check, travel gap feasibility, pace-based daily duration caps (relaxed 8h, balanced 10h, packed 12h), total budget and per-day cap limits, locked items immutability.
   - `altitude.py`: Altitude gain rate validation (safe acclimatization thresholds for high-altitude destinations like Ladakh/Sikkim), mapped cleanly to `day_too_long` code with medical disclaimer.
   - `seasonal.py`: Seasonal road and pass accessibility verification (monsoon/winter closures), mapped to `closed` code.
   - `permits.py`: Detection of permit requirements (ILP/PAP/RAP) and permit office closure checks.
   - `impact_rules.py`: Signal-to-disruption mapping (weather threshold >= 0.6 precip or snow/visibility, closure, delay >= 30 min, budget overrun >= 10%), deduplication fingerprinting.
   - Unit tests covering edge cases and property-based tests via Hypothesis.

3. **Destination Registry and Seed Catalog (`agents/data/seed/`, `reroute_agents/destinations/`)**:
   - Curated JSON seed catalogs (15-30 verified places each) for Darjeeling, North Sikkim, Arunachal Pradesh, and Ladakh, adhering to `places` schema.
   - `routes.json`: Approximate travel times and distances between key regional hubs.
   - `registry.py`: Dynamic destination registry and repository loader.
   - `data/README.md`: Documentation of places, confidence flags, and unverified records.

4. **Tools Layer (`reroute_agents/tools/`)**:
   - LangChain `@tool` implementations with Pydantic arguments: `search_places`, `get_place_details`, `get_weather_forecast` (Open-Meteo), `estimate_route` (routes.json / ORS / mountain multiplier), `convert_currency` (Frankfurter API), `get_expenses_summary`.
   - Caching via repository, timeout and retry decorators, structured error handling (`{"ok": false, ...}`).
   - `injector.py`: Disruption injector for synthetic simulation testing.

5. **LLM Prompts and Core Graphs (`reroute_agents/prompts/`, `reroute_agents/nodes/`, `reroute_agents/graphs/`)**:
   - Versioned Markdown prompts in `prompts/*.md` (intake, planner, replanner, chat).
   - Nodes: `intake.py`, `researcher.py`, `planner.py`, `validator.py`, `budget_check.py`, `finalize.py`, `collect_signals.py`, `impact_analyzer.py`, `replanner.py`, `build_proposal.py`, `apply_changes.py`.
   - `plan_graph.py`: Bounded feedback loop (max 3 iterations) with timeline event emission.
   - `replan_graph.py`: Disruption assessment, targeted replanning, proposal diff construction, `interrupt()` pause, and resume handling (`approve`, `reject`, `alternatives`).
   - `chat_graph.py`: ReAct travel assistant with tool calling and proposal routing for edits.

6. **Public Gateway and Worker (`reroute_agents/gateway.py`, `reroute_agents/monitor.py`)**:
   - Async generators: `run_plan`, `run_replan`, `resume_replan`, `run_chat` yielding `AgentEvent`.
   - Error trapping, cancellation safety, and execution logging.
   - `monitor.py`: Background trip evaluation with cheap-rule filtering and deduplication.

7. **CLI Runner, Test Suites, and Evaluation (`agents/cli.py`, `agents/tests/`, `agents/evaluation/`)**:
   - CLI commands: `plan`, `simulate`, `check-rules`, with `--fake-llm` and `--mock-tools`.
   - Unit, graph, contract, and invariant test suites.
   - Evaluation suite: 20 scripted trips and 10 disruption scenarios, reporting against PRD targets in `agents/evaluation/RESULTS.md`.

8. **Documentation and Notes (`agents/README.md`, `agents/INTEGRATION_NOTES.md`, `agents/DECISIONS.md`)**.

## 3. Assumptions

- Python 3.11+ environment with async capabilities and PostgreSQL checkpointing compatibility.
- In-memory repositories will serve CLI and test workflows without requiring a live PostgreSQL instance.
- The backend will inject database sessions or provide concrete repository implementations matching Protocol interfaces.
- Checkpointing uses MemorySaver during testing and CLI execution, and AsyncPostgresSaver when supplied in production.
- Model names are configured via environment fallback chains rather than hardcoded.
- Travel time estimation in mountain regions defaults to seed/mountain-road multipliers when remote routing APIs are unavailable or unkeyed.

## 4. Conflicts and Gaps Identified in Specs

- **Location and Import Path of Package**:
  `docs/03_ARCHITECTURE.md` references `app/agents/` within the backend tree, while the prompt requires all work to reside strictly in `agents/` under package `reroute_agents`.
  *Resolution*: Package is built as `reroute_agents` inside `agents/`. Integration instructions are documented in `agents/INTEGRATION_NOTES.md` explaining how the backend can install or import it.
- **V1 Destination Scope**:
  `docs/01_PRD.md` lists Kolkata, Darjeeling, Goa, Jaipur as examples. Section 3 of the prompt mandates the four Himalayan and North-East regions (Darjeeling, North Sikkim, Arunachal Pradesh, Ladakh).
  *Resolution*: As instructed, the prompt's explicit V1 scope takes precedence for the destination catalog and specialized rules.
- **Violation and Disruption Enum Constraints**:
  The contract in `docs/05_API_AND_AGENT_CONTRACT.md` restricts `Violation.code` to `Literal["closed","overlap","travel_too_long","over_budget","day_too_long","locked_changed"]` and `DisruptionEvent.type` to predefined types.
  *Resolution*: Regional rules (altitude, permits, seasonal closures) are mapped into existing codes (`day_too_long`, `closed`, `delay`) with specific diagnostic details stored in `detail` or `data` payloads.
- **Resume Decision Signature**:
  `docs/05_API_AND_AGENT_CONTRACT.md` Section 3 signatures list `resume_replan` accepting `Literal["approve","reject"]`, but Section 1 defines three user decisions: `approve`, `reject`, and `alternatives`.
  *Resolution*: `resume_replan` accepts `Literal["approve","reject","alternatives"]`.
- **Database Driver Independence**:
  `docs/05_API_AND_AGENT_CONTRACT.md` includes `db: AsyncSession` in gateway signatures, but hard rules mandate no direct DB driver dependencies in `reroute_agents`.
  *Resolution*: An optional repository bundle or session adapter is supported, defaulting to protocol-based repositories so the agent engine is completely decoupled from SQLAlchemy/asyncpg drivers.
